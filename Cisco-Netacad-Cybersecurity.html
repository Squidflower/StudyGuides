CP1Modules 1–6

Network Security

Who attacks networks and why, the malware and social-engineering they use, the weaknesses in TCP/IP itself, and the devices that defend the perimeter.

M1Cybersecurity Threats, Vulnerabilities, and Attacks

A threat is a potential danger, a vulnerability is a weakness that a threat can exploit, and an attack is the act of exploiting it. Security exists to protect the value of data, so the module starts by classifying who the attackers are and what tools they use.

Threat actors

Ranked roughly by skill and motive: script kiddies (little skill, borrowed tools), hacktivists (political/social motive), organized crime (financial motive, professional), state-sponsored actors (espionage, sabotage of critical infrastructure), and insiders (employees/contractors whose existing access makes them especially dangerous). The old "hat" labels still appear: white hat (authorized/ethical), gray hat (unauthorized but non-malicious disclosure), black hat (malicious, illegal).

Malware families

A virus attaches to a host file and needs a user to run it to spread. A worm is self-contained and self-propagates across networks with no host and no user action — which is why worms spread far faster. A Trojan hides malicious function inside something that looks legitimate. A rootkit buries itself at the OS/kernel level to hide and keep privileged access. Ransomware encrypts data for extortion; spyware/adware monitor or serve ads; a logic bomb waits for a trigger (a date or event); a backdoor/RAT gives covert remote access.

Social engineering

Attacks that manipulate people rather than machines. Phishing is mass fraudulent email; spear phishing is targeted; whaling targets executives; vishing uses voice calls; smishing uses SMS. Pretexting invents a believable scenario, tailgating follows someone through a secure door, and dumpster diving harvests discarded information.

Network-based attacks

DoS overwhelms a service from one source; DDoS uses a botnet of compromised "zombie" hosts coordinated by a handler. Man-in-the-middle (MitM) secretly relays/alters traffic between two parties. Spoofing falsifies identity at the IP, MAC, ARP, or DNS level.

The CIA triad (introduced here)

Confidentiality keeps data secret from the unauthorized, integrity keeps it accurate and unaltered, and availability keeps it accessible when needed. Every control in the course maps back to one of these three goals.

Watch for: virus vs. worm hinges on two things — a worm self-replicates and needs no host file or user action. And remember social engineering exploits human trust, not a software flaw.

M2Securing Networks

Introduces the mindset and building blocks of defense — thinking about the whole attack surface rather than a single wall.

Attack surface

The sum of all points where an attacker could try to get in, across three dimensions: the network surface (open ports, exposed services), the software surface (application code, APIs), and the human surface (users susceptible to social engineering). Good security shrinks each of these.

Defense-in-depth

No single control is trusted to stop everything, so defenses are layered — if one fails, another still stands. The course contrasts the security onion (peel back layer after layer of protection) with the security artichoke (a modern reality where attackers can pull off individual "leaves" to reach the core without going through every layer).

Security devices & the SOC

Core tools include firewalls, IDS/IPS, VPN gateways, proxies, and NAC (network access control). A Security Operations Center (SOC) staffs analysts in tiers who monitor, triage, and respond using documented playbooks.

M3Attacking the Foundation

TCP/IP was designed for connectivity, not security, so many attacks exploit the protocols themselves.

The TCP three-way handshake

TCP is connection-oriented: a client sends SYN, the server replies SYN-ACK, and the client confirms with ACK before data flows. Because the server allocates resources on the first SYN, this handshake can be abused.

TCP vs. UDP attacks

A SYN flood sends many SYNs but never completes the handshake, filling the server's connection table. Session hijacking and TCP reset (RST) attacks tamper with an established session. UDP is connectionless (no handshake), so a UDP flood simply drowns the target in traffic.

Address- and name-layer attacks

ARP spoofing/poisoning lets an attacker associate their MAC with another host's IP to intercept LAN traffic. DNS attacks include spoofing, cache poisoning, and tunneling (smuggling data inside DNS). DHCP spoofing/starvation hands victims a rogue gateway/DNS or exhausts the address pool. ICMP is abused for reconnaissance (ping sweeps) and tunneling.

Watch for: know which attacks rely on TCP being connection-oriented (SYN flood, hijacking, RST) versus UDP being connectionless (UDP flood).

M4Attacking What We Do

Moves up the stack to the applications, web services, and credentials people use every day.

Application & memory attacks

A buffer overflow writes past a memory boundary to overwrite adjacent data or inject code, often enabling remote code execution. Poor input validation is the root cause of most of these.

Web attacks

SQL injection inserts malicious database commands through unvalidated input. Cross-site scripting (XSS) injects scripts that run in other users' browsers. CSRF tricks a logged-in user's browser into making unwanted requests. Directory traversal reaches files outside the intended web folder.

Credential attacks

Brute force tries every combination; a dictionary attack tries likely words; rainbow tables reverse unsalted hashes; password spraying tries one common password across many accounts to dodge lockouts; pass-the-hash reuses a captured hash without cracking it.

Advanced Persistent Threat (APT)

A well-resourced adversary that establishes a stealthy, long-term foothold and moves in multiple phases, prioritizing persistence and evasion over quick payoff.

M5Wireless Network Communication

Radio is a shared, invisible medium anyone in range can listen to, so wireless needs strong encryption and authentication.

Wi-Fi security evolution

WEP is broken and must never be used. WPA improved on it but is dated. WPA2 uses AES/CCMP and is the modern baseline; WPA3 adds stronger key exchange and protection for open networks.

Wireless threats

A rogue AP is an unauthorized access point on your network; an evil twin impersonates a legitimate SSID to harvest connections. Deauthentication attacks force clients off to capture handshakes, jamming denies service, and war driving maps vulnerable networks. Bluetooth has bluejacking (unsolicited messages) and bluesnarfing (data theft).

Weak "controls" that aren't real security

Hiding the SSID and MAC address filtering are trivially bypassed — SSIDs still appear in client probes and MACs are easily spoofed. Genuine protection comes from WPA2/WPA3 encryption and strong authentication.

M6Network Security Infrastructure

The physical and logical devices that enforce policy at the network boundary and inside it.

Topology & the DMZ

A DMZ (screened subnet) is a buffer network for public-facing servers (web, mail) that sits between the internet and the trusted internal network, so a compromised public server doesn't directly expose the inside.

IDS vs. IPS

An IDS sits out-of-band (analyzing a copy of traffic) and can only detect and alert — it never blocks, so it can't slow traffic but also can't stop an attack in progress. An IPS sits inline and can detect and drop malicious packets, at the risk of blocking legitimate traffic if mistuned.

Consolidated appliances

NGFW (next-gen firewall) adds application awareness and IPS; UTM bundles firewall, antivirus, filtering, and VPN in one box; content filters and VPN gateways round out the perimeter. ACLs on routers provide basic traffic filtering (demonstrated in Packet Tracer).

CP2Modules 7–10

OS and Endpoint Security

Because most attacks eventually land on a host, you need to understand how Windows and Linux work, how to protect the endpoint, and the model that frames all security decisions.

M7The Windows Operating System

Windows dominates the enterprise desktop, so knowing its internals is essential for both defending and investigating it.

Architecture

Code runs in user mode (limited) or kernel mode (full hardware access); keeping most code in user mode limits damage. The OS schedules work as processes, which contain threads, which use handles to reference resources (files, keys).

The Registry

A hierarchical database of system and application settings. Key hives include HKLM (machine-wide) and HKCU (current user). Attackers plant autorun keys here for persistence, which makes the Registry a prime forensic target.

File systems & tooling

NTFS supports permissions, auditing, and encryption (EFS); older FAT does not. Administrative/investigative tools include Task Manager, Event Viewer (logs), PowerShell, and netstat (active connections).

Built-in security

UAC prompts before privilege elevation, Windows Defender provides antimalware, BitLocker encrypts the disk, and Windows Firewall filters host traffic.

M8Linux Overview

Linux runs most servers and security tooling (including Kali), so analysts must be comfortable at the shell.

Shell & filesystem

Everything is a file under a single tree starting at /. Core commands: ls, cd, cat, grep (search), ps (processes), chmod/chown (permissions/ownership).

Permissions and octal notation

Each file has read/write/execute bits for owner, group, and other. In octal, read = 4, write = 2, execute = 1, summed per role: rwx = 7, r-x = 5, r-- = 4, so rwxr-xr-- = 754. root is the superuser; ordinary users elevate with sudo.

Logs & services

System events go to syslog (e.g. under /var/log); reading server logs is a core skill. A port scanner such as Nmap reveals which services (open ports) a host is exposing.

M9System and Endpoint Protection

The endpoint (laptop, server, phone) is where users work and where malware ultimately executes, so it gets its own defensive stack.

Antimalware detection methods

Signature-based detection matches files against a database of known-malware patterns — fast and accurate for known threats, but blind to anything new. Heuristic/behavioral detection flags suspicious behavior, so it can catch novel or zero-day malware that has no signature yet.

Host controls

HIDS/HIPS monitor a single host for intrusions; a host-based firewall filters that machine's traffic; application allow/deny-listing controls what may run; EDR adds continuous recording and response; sandboxing detonates suspicious files in isolation.

Hardening

Reduce the endpoint's attack surface: apply patches promptly, disable unneeded services and default accounts, and establish a secure baseline to measure drift against.

M10Cybersecurity Principles, Practices, and Processes

This module formalizes the mental model used to reason about any security decision: the McCumber Cube.

The McCumber (Cybersecurity) Cube

A 3×3×3 framework with three axes. Principles — what you protect: confidentiality, integrity, availability. States of data — where it is: in transit (moving across a network), at rest (stored), in process (being used/computed). Safeguards — how you protect it: technology, policy & practice, and people (education/training/awareness).

Protecting each data state

Data in transit is protected by TLS/VPN/IPsec; data at rest by disk/file encryption and access controls; data in process by secure coding and memory protections. Integrity is verified with hashing; confidentiality is enforced with encryption (both practiced in Packet Tracer).

Watch for: the classic question gives a scenario and asks you to name one item from each axis — e.g. "a doctor encrypts a patient file saved on a USB drive" = confidentiality (principle) + data at rest (state) + technology (safeguard).
CP3Modules 11–13

Principles, Practices, and Processes of Network Defense

Turning the theory into an operating defense: layered strategy, hardening the network, and controlling who can do what.

M11Understanding Defense

How organizations structure protection so that no single failure is catastrophic.

Defense-in-depth levers

Six reinforcing ideas: layering (multiple independent controls), redundancy (backups/failover), diversity (different vendors so one flaw doesn't break every layer), limiting (least privilege/need-to-know), obscurity (don't advertise details — a supplement, never the sole defense), and simplicity (complex systems are harder to secure).

The policy hierarchy

Policies state high-level intent; standards make requirements mandatory and specific; guidelines are recommended best practice; procedures are the exact step-by-step instructions. Each layer gets more detailed and concrete.

Monitoring

Organizations detect threats by collecting logs, generating alerts, and consuming external threat feeds, then correlating them (often in a SIEM) to spot patterns a single source would miss.

M12System and Network Defense

Concrete hardening across the application, protocol, network, and physical dimensions.

Application security

Build security in: secure coding, rigorous input validation, and testing against the OWASP Top 10 (the most common web-app risks such as injection and broken access control).

Hardening services & protocols

Replace insecure protocols with encrypted equivalents — e.g. use SSH instead of cleartext Telnet, and HTTPS instead of HTTP — and turn off services you don't use to shrink the attack surface.

Segmentation & physical security

Network segmentation with VLANs and subnets contains a breach to one zone and limits lateral movement. Physical security (locks, badges, cameras, mantraps) still matters — including for IoT devices, which are often deployed in exposed locations.

M13Access Control

Deciding who may access what, and proving it, is the heart of confidentiality and integrity.

AAA

Authentication proves identity, Authorization grants permissions, and Accounting logs what was done — together the backbone of access control.

Authentication factors & MFA

Factors fall into categories: something you know (password/PIN), something you have (token/smart card), something you are (biometrics). Multifactor authentication requires factors from different categories — two passwords is still single-factor.

Access control models

MAC (mandatory) is strictest: a central authority assigns labels/clearances and owners cannot override them (military use). DAC (discretionary): the resource owner decides who gets access. RBAC (role-based): permissions attach to job roles. ABAC/rule-based: access is decided by attributes and rules. Underpinning all of them: least privilege and separation of duties.

TACACS+ vs. RADIUS

Both are server-based AAA protocols. TACACS+ is Cisco-proprietary, runs over TCP, encrypts the entire payload, and separates authentication, authorization, and accounting. RADIUS is an open standard, runs over UDP, encrypts only the password, and combines authentication with authorization.

CP4Modules 14–18

Firewalls, Cryptography, and Cloud Security

The most point-dense group. Traffic filtering with ACLs and firewalls, securing cloud workloads, and the cryptography that underpins confidentiality, integrity, and trust.

M14Access Control Lists

ACLs are ordered rule lists on routers/switches that permit or deny traffic — the most basic packet filter.

Standard vs. extended

A standard ACL can match only the source IP. An extended ACL matches source and destination IP, the protocol, and port numbers — far more precise. ACLs can be numbered or named.

Placement rules

Place a standard ACL close to the destination — because it only knows the source, putting it early would over-block legitimate traffic. Place an extended ACL close to the source so unwanted traffic is dropped before it consumes bandwidth.

Wildcard masks & implicit deny

ACLs match addresses using a wildcard mask, which is the inverse of a subnet mask (0 = must match, 1 = ignore). Every ACL ends with an invisible implicit deny all, so at least one permit is required or everything is blocked. IPv6 ACLs follow the same logic.

M15Firewall Technologies

Firewalls enforce a boundary policy; they differ mainly in how much context they track.

Firewall types

Packet-filtering (stateless) checks each packet against static rules with no memory of prior packets. Application/proxy firewalls inspect at the application layer and can terminate connections. NAT firewalls hide internal addresses. NGFW combines deep inspection, application awareness, and IPS.

Stateful vs. stateless

A stateful firewall keeps a state table of active connections, so it automatically allows legitimate return traffic and blocks unsolicited packets — more secure and the modern default. A stateless firewall evaluates every packet in isolation.

M16Zone-Based Policy Firewalls (ZPF)

Cisco's modern IOS firewall model, which applies policy between named security zones instead of per-interface rules.

Building blocks

Interfaces are assigned to security zones (e.g. INSIDE, OUTSIDE, DMZ). A zone pair defines a direction of traffic between two zones. Class maps identify traffic, policy maps decide the action (inspect/pass/drop), and a service policy binds the policy to the zone pair.

Default behavior

Traffic between different zones is denied unless a policy explicitly permits it; traffic within the same zone flows freely by default. Configured and tested in Packet Tracer.

M17Cloud Security

Moving workloads to the cloud changes who is responsible for which controls.

Service & deployment models

Service models: IaaS (you rent infrastructure), PaaS (you rent a platform to run code), SaaS (you consume a finished application). Deployment models: public, private, hybrid, and community.

Shared responsibility model

The provider always secures the physical infrastructure and hypervisor. The customer's share grows as you move down the stack: in IaaS the customer secures the guest OS, applications, and data; in SaaS the customer is mainly responsible for their data and access management.

Threats & controls

Leading cloud risks are misconfiguration, insecure APIs, and data breaches. Controls include encryption, strong IAM, and a CASB to enforce policy across cloud apps. Virtualization/containers add hypervisor and image security concerns.

M18Cryptography

The mathematical backbone of confidentiality, integrity, authentication, and non-repudiation.

Symmetric vs. asymmetric encryption

Symmetric uses one shared secret key to encrypt and decrypt — very fast, ideal for bulk data (DES, 3DES, AES) — but the key must be exchanged securely. Asymmetric uses a mathematically linked key pair: data encrypted with the public key can only be decrypted with the private key. It's slower but solves key distribution (RSA, Diffie-Hellman, ECC). In practice, asymmetric crypto securely exchanges a symmetric session key, then symmetric crypto does the heavy lifting.

Hashing (integrity)

A hash is a one-way function producing a fixed-length digest; you cannot reverse it to recover the input. It proves integrity — recompute the hash and compare. MD5 and SHA-1 are broken/deprecated; use SHA-2 (SHA-256) or SHA-3. A collision (two inputs, same hash) is a weakness. Passwords are salted before hashing to defeat rainbow tables. HMAC adds a secret key to a hash, giving integrity and authentication.

Digital signatures & PKI

To sign, you hash the message and encrypt the hash with your private key. Anyone can verify with your public key, which proves integrity, authentication, and non-repudiation (you can't deny sending it). PKI makes this trustworthy at scale: a Certificate Authority (CA) issues X.509 certificates binding a public key to a verified identity.

Steganography

Hides the very existence of a message by embedding it inside another file (image/audio). Encryption hides the content but not the fact that a secret exists; steganography hides the fact itself.

Watch for: direction of keys. Encrypt for confidentiality with the recipient's public key (only they can open it). Sign for authenticity with your own private key (anyone can verify it).
CP5Modules 19–21

Evaluating Security Alerts

The analyst's job: know which protocols carry (and hide) evidence, what security data looks like, and how to separate real attacks from noise.

M19Technologies and Protocols

Monitoring depends on understanding the protocols that both reveal and conceal activity.

Protocols you monitor

Syslog centralizes logs, NTP keeps timestamps aligned (essential for correlating events), DNS and HTTP/HTTPS dominate traffic, and ICMP/SSH appear in recon and administration.

Protocols that hinder monitoring

HTTPS/TLS encryption hides payloads; tunneling, TOR, NAT/PAT, and peer-to-peer traffic all obscure the true source, destination, or content — challenges every analyst must account for.

Visibility tools

NetFlow records metadata about every flow (who talked to whom, how much) even when the payload is encrypted; a SIEM aggregates and correlates logs from many sources into actionable alerts.

M20Network Security Data

Different data types give different views of an incident; analysts combine them.

Types of security data

Alert data (IDS/IPS verdicts), session/transaction data (records of connections), full packet capture (the complete traffic, storage-heavy but definitive), statistical data (baselines/anomalies), and log data (from hosts and applications).

Sources & tools

Data comes from IDS/IPS, firewall, proxy, and endpoint logs plus NetFlow. Analysts use tcpdump and Wireshark for packet analysis and Zeek for rich connection logs.

M21Evaluating Alerts

Alerts are only useful once you can judge whether they're real and place them in the attacker's timeline.

Alert classification

True positive: alarm fired, threat was real. False positive: alarm fired on benign activity (noise that wastes analyst time). False negative: no alarm, but a real attack occurred — the most dangerous outcome because it goes unnoticed. True negative: correctly quiet. Tuning aims to cut false positives without creating false negatives.

Detection rules

Snort is a signature-based IDS/IPS whose rules specify what traffic to match and what action to take; well-written rules reduce false positives.

Analysis frameworks

The Cyber Kill Chain models an attack in stages (reconnaissance → weaponization → delivery → exploitation → installation → command & control → actions on objectives). The Diamond Model relates adversary, capability, infrastructure, and victim. MITRE ATT&CK is a detailed knowledge base of real adversary tactics and techniques (TTPs) used to map and hunt threats.

CP6Modules 22–26

Vulnerability Assessment and Risk Management

Governing security lawfully, testing systems, consuming threat intelligence, scoring weaknesses, and quantifying risk so leaders can decide what to fix first.

M22Governance and Compliance

Security operates inside legal and ethical boundaries; governance sets direction and holds the organization accountable.

Ethics & governance

Governance defines roles, oversight, and acceptable use. Professional conduct follows codes such as the ISC² Code of Ethics. Note that legal and ethical are not the same — an action can be one without the other.

Laws & regulations (match to the data)

HIPAA — health information. FERPA — student education records. GLBA — financial institutions' customer data. SOX — corporate financial reporting/accountability. PCI DSS — payment-card data (an industry standard, not a law). GDPR — EU personal data.

Frameworks

The ISO/IEC 27000 series provides an information-security management standard. The NIST Cybersecurity Framework organizes work into five functions: Identify, Protect, Detect, Respond, Recover.

M23Network Security Testing

You can't defend what you haven't tested; testing finds weaknesses before attackers do.

Scanning vs. penetration testing

Vulnerability scanning identifies and catalogs weaknesses automatically but does not exploit them. Penetration testing goes further and actively exploits weaknesses to prove real-world impact and chain-ability.

Techniques & tools

Common tools: Nmap (port/host discovery), Nessus/OpenVAS (vulnerability scanners), Metasploit (exploitation framework), Wireshark (packet analysis), and Kali Linux (the pen-testing distro). Engagements are black-box (no prior knowledge), white-box (full knowledge), or gray-box (partial).

M24Threat Intelligence

Knowing what adversaries are doing elsewhere lets you defend proactively.

Sources

OSINT (open sources), commercial feeds, the CVE database (catalog of known vulnerabilities), industry ISACs (sharing communities), and government bodies such as CISA.

Sharing standards & indicators

STIX is a standard format for expressing threat information; TAXII is the protocol that transports it. An Indicator of Compromise (IoC) is evidence a breach already happened (a bad hash/IP); an Indicator of Attack (IoA) reflects behavior of an attack in progress.

M25Endpoint Vulnerability Assessment

Systematically finding, scoring, and remediating weaknesses on hosts.

Profiling the attack surface

Build a network profile and server profile (normal ports, traffic, and behavior) so deviations stand out as potential compromise.

CVSS

The Common Vulnerability Scoring System rates severity on a 0–10 scale using three metric groups: Base (intrinsic characteristics), Temporal (how it changes over time, e.g. exploit availability), and Environmental (impact in your specific environment). Scores map to Low → Critical for prioritization.

Vulnerability management lifecycle

A repeating cycle: discover → prioritize (often by CVSS) → remediate (patch/mitigate) → verify, supported by asset, patch, and change management.

M26Risk Management and Security Controls

Risk is unavoidable; the job is to measure it and decide how to handle it.

What risk is

Risk combines a threat, a vulnerability it can exploit, and the impact if it does (risk = threat × vulnerability × impact). You reduce risk by removing the vulnerability or lowering the impact.

The four risk responses

Avoid (stop the risky activity), Transfer (shift impact to a third party, e.g. insurance), Mitigate (add controls to reduce it), or Accept (acknowledge and live with it when cost outweighs benefit).

Quantifying loss

SLE (single loss expectancy) = asset value × exposure factor — the cost of one incident. ARO (annual rate of occurrence) = how many times per year it's expected. ALE = SLE × ARO gives the expected annual loss, which justifies spending on controls.

Control types & functions

Controls are grouped by type — administrative (policies/training), physical (locks/guards), technical (firewalls/encryption) — and by function: preventive, detective, corrective, deterrent, compensating, and recovery.

CP7Module 27

Incident Response

What to do when prevention fails: investigate rigorously, contain and recover, and get the business back on its feet.

M27Digital Forensics and Incident Analysis and Response

Incident response is a disciplined process, and forensics is the careful handling of evidence that supports it.

The NIST incident-response lifecycle

Four phases in order: Preparation (tools, plans, training before anything happens) → Detection & Analysis (identify and scope the incident) → Containment, Eradication & Recovery (stop the spread, remove the threat, restore service) → Post-incident activity (lessons learned to improve future response). A CSIRT executes this using playbooks.

Digital forensics

Order of volatility says to collect the most perishable evidence first — CPU registers, RAM, and running state are lost on shutdown, so capture them before disk images. Chain of custody documents who handled each piece of evidence, when, and how, preserving its integrity and legal admissibility.

Business continuity & disaster recovery

BCP keeps the business running through disruption; DRP restores IT afterward. Two key targets: RPO (recovery point objective) = the maximum tolerable data loss, measured as a point in time; RTO (recovery time objective) = how long restoration may take. Both drive backup frequency and redundancy design.

Watch for: RPO is about data loss (how far back), RTO is about downtime (how long to restore) — questions frequently swap the two.
